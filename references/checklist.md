# 企业 AI 管理层复盘清单

> 用于老板带核心管理层完成一次 60–90 分钟复盘。目标是选出一个最值得先理顺的工作内容，不是选择工具或设计试点。

## 复盘结束时应得到什么

1. 未来 3–6 个月最想改善的业务结果；
2. 3–5 件真实经营问题；
3. 一条关键业务链上的主要断点；
4. 各关键部门的高频工作与痛点；
5. 一个管理层共同选定的优先工作内容（线头候选）。

---

## 表 01｜企业背景：先对齐公司要改什么

由老板或总经办先准备，管理层补充：

1. 公司 / 行业 / 团队规模；
2. 主要收入来源和业务结构；
3. 未来 3–6 个月最想改善的 1–2 个业务结果；
4. 最近半年最头疼的 3–5 件事：在哪条业务链、谁遇到、发生了什么、造成什么后果；
5. 如果未来三个月只能改一件事，最该改什么，为什么。

**写法示例：**

> 销售把客户聊天转给策划时，经常缺预算、决策人和交付时间；策划需要再问一轮，方案平均改 2–3 版，报价和排期延后。

不要只写“效率低”“协同差”“员工执行力不够”。

---

## 表 02｜流程自查：问题卡在点还是线

### A. 勾选已经发生的现象

- 员工各自用 AI，但部门之间结果对不上；
- 工具买了、培训做了，交付周期或返工没有改善；
- 时间耗在交接、等待、返工，不在个人电脑里；
- 各部门自行找工具，没有共同方向；
- 工具很多，但没有一条业务链真正跑通；
- 工具配了，流程、责任和验收没有改变。

### B. 还原一条真实业务链

按实际顺序写 3–6 步：谁发起、收到什么、交出什么、资料在哪里、最常卡在哪里、谁负责接住。

**示例：**

> 销售获客 → 首次沟通 → 需求记录 → 转策划 → 需求简报（Brief）确认 → 方案初稿 → 客户反馈 → 定稿。

### C. 会议结论

只回答：

1. 这个问题更像个人动作慢（点），还是跨部门交接问题（线）？
2. 最该先理顺的断点是什么？
3. 在讨论 AI 前，流程、责任或资料上要先讲清什么？

## 表 03｜部门盘点：先不谈 AI

默认从以下部门开始：

| 部门 | 负责人应带来的信息 |
| --- | --- |
| 总经办（老板） | 经营重点、跨部门反复问题、决策卡点 |
| 人事行政培训 | 人员流程、标准执行、培训与行政支持的重复问题 |
| 财务部 | 合同、请款回款、预算核算、经营数据的衔接问题 |
| 销售部 | 获客、跟进、需求收集、转交项目部的问题 |
| 项目部（策划 / 设计 / 制作交付） | 需求拆解、方案、排期、版本和交付问题 |
| 技术 / 市场推广 / 采购 / 其他 | 仅在与当前经营问题直接相关时加入 |

每位关键部门负责人至少提供两行：

- 高频工作 / 场景；
- 真实痛点；
- 类型（重复 / 繁琐 / 有壁垒 / 高风险）；
- 是否跨部门，以及相关上下游部门。

此表不讨论 AI，不要求每个部门都做项目。

---

## 表 04｜优先事项：选出一个线头候选

将表 03 中的候选工作内容放在一起讨论，每项 0–5 分：

| 标准 | 通俗判断 |
| --- | --- |
| 高频 | 是否经常发生，影响足够大？ |
| 痛苦 | 是否带来返工、等待、漏信息、丢机会或扯皮？ |
| 可衡量 | 是否能看出改善前后差别？ |
| 风险可控 | 是否能先理顺，而不直接做对外承诺或敏感决策？ |

最后由老板拍板，只确定：

1. 选定的优先工作内容；
2. 它解决的业务问题；
3. 为什么排第一；
4. 哪些部门共同牵头；
5. 下一步是进入试点设计讨论，还是先补流程、责任、资料基础。

**本表到此结束。** 不选择 AI 工具，不定技术方案，不承诺自动化。
